| 2026-10-27 | PG0 review, the database design in detail. (1) Transactions open through a domain port `Transactor.run { }`, implemented in `data` over `Database.tx`; repositories join it through the coroutine context and `Store.commit` is built on it; the block holds repository calls only (Konsist checks `usecases`), and every read-dependent decision (version checks, phone and provider claims, member cap, successor, last-ack media delete) runs inside one `run`. (3) M6 reads the newest message id per chat from `message_records (chat_id, message_id DESC)`; `lastMessageId` is null after 30 quiet days. (4) `inbox`, `group_messages` and `message_records` are partitioned by `RANGE (message_id)` with daily UUIDv7 bounds, keyed `(user_id, message_id)`, `(chat_id, message_id)` and `(message_id)`; ids are UUIDv7 made on the server. (5) Media rows expire by `expires_at`; every path locks `media` before `media_pending`. Membership transactions lock the `chats` row before `members`; the 1,000 cap is a conditional `member_count` update. (9) Tables are plural snake_case, except the terms `outbox`, `realtime`, `audit`, `history` and `usage_daily`; `expires_at` always means filtered and purged. (A) The app pool logs in as `circaso_app` (5 s statement, 2 s lock, 10 s idle in transaction) and the jobs pool as `circaso_jobs` (60 s statement), both granted the module roles. (B) `Migrate` logs in as `circaso_migrator` (`CREATEROLE`, owns the schemas, `DATABASE_MIGRATION_PASSWORD`), created once from `deploy/postgres/initdb`, and runs each module's Flyway with `SET ROLE <module>` so the module role owns its tables. (C) identity accounts get `delete_after`, with a partial index for the job that completes deletion | The domain can't import Exposed, so the transaction boundary needs a port; a decision made outside the transaction that writes it is a race. A fixed lock order prevents deadlocks and makes succession see a settled member list. Transition guards order webhooks by meaning, not arrival. Separate login roles give purges their own limits without loosening the app's. Pasaka: "go with your recommendations" | Infrastructure, identity, users, messaging, wallet, assistant, deploy |

## Open questions

Not decided yet. Where code depends on one of these, build behind an interface or config value and leave a `TODO(decision: …)` rather than picking an answer.

- [x] **When the account turns active.** Decided 2026-10-21: at device registration (I6).
- [ ] **What a blocked or unconnected person is told.** Proposed: a handle with lookup turned off answers `users.handle_not_found`, like one that doesn't exist; any action toward someone you can't reach answers `users.not_reachable`, never saying whether it's a block or a missing connection.
- [ ] **Hosting for the app, Redis and monitoring.** The database is on ScyllaDB Cloud; the app containers, Redis and the Grafana stack still need a home. Money in production should not depend on a home connection.
- [ ] **Signing key storage.** Environment secret for the pilot; which key store before real money moves.
- [ ] **Support recovery tooling.** The ops screen, the KYC vendor and the selfie match that recovery relies on.
- [ ] **Unique lookup index in Kandra.** An optional Kandra feature (`@LookupIndex(unique = true)`) that would replace the three claim tables.
- [ ] **CI/CD and environments.** How a build reaches staging and production, who approves a production deploy, and where the one-shot migration step runs.
- [ ] **Backups and disaster recovery.** ScyllaDB Cloud's backup schedule and a tested restore; Redis AOF backups; how long the service may be down and how much data it may lose.
- [ ] **Kenya Data Protection Act.** Registering with the Office of the Data Protection Commissioner as a data controller and processor, a retention schedule per table, and how account deletion reaches every module.
- [x] **Creating the Circle user.** Decided 2026-10-25: on demand, when the user creates a wallet from the wallet section.
- [x] **Reading history on a new phone.** Decided 2026-10-25: (b) plus (a). The old phone hands the history key to the new one by QR when both are present; otherwise it comes from a passphrase-sealed backup.
- [ ] **Wallet: chain.** Proposed: USDC on Base, smart-contract accounts (SCA), gas sponsored through Circle Gas Station. Alternatives: Polygon, Solana, Arc once on mainnet.
- [ ] **Wallet: Circle authentication method.** Proposed: PIN with security questions, plus biometrics; or social login or email OTP.
- [ ] **Wallet: who pays gas.** Proposed: Circaso sponsors all gas in v1, with per-wallet daily caps.
- [ ] **Wallet: limits, KYC and licensing.** Limits for unverified and verified accounts; whether Kenya's Virtual Asset Service Providers Act, 2025 requires a licence for user-controlled wallets.
- [ ] **Wallet: record retention** after account deletion.
- [ ] **Wallet: deletion error code.** `identity.wallet_not_empty` (published to the app) or the guard's own `wallet.funds_remaining` (the `DeletionGuard` contract).
- [ ] **Wallet: showing KES.** A rate source for KES amounts next to USDC.
- [x] **Messaging: rate limit on phone frames.** Decided 2026-10-25: at most 100 frames per second per socket.
- [ ] **Messaging: passkey domain files.** `circaso.com` must serve `/.well-known/assetlinks.json` and `/.well-known/apple-app-site-association` for the backup passkey; who owns the site and the app's signing fingerprint and team id.
- [ ] **Payment hold after a support restore.** The sign-in flow keeps a 48-hour hold on outgoing transfers after an account is relinked (ID-23), on top of the 48-hour notice before it. Identity has no status for it yet. Keep it (it would live in the wallet, keyed on `AccountRelinked`) or drop it because the notice already gives the owner time to cancel?

- [ ] **Where the assistant runs.** Inside the gateway, or as its own `assistant` module (Koog agent, its prompts, its conversation history) whose tools call the `/v1/agent/` routes with the agent token. The gateway holds no business logic today, which favours its own module.
