| 2026-11-08 | **Staff edit fees and limits through `FeeAdmin`, wallet's second staff contract** (Pasaka: "an option where I can adjust fees"; the details made by the backend session, for Pasaka to confirm). ADMIN changes (`fees.manage`), FINANCE and ADMIN read (`fees.read`). (1) **A change is a new version, never an overwrite**: the latest version's `effective_to` becomes the new version's `effective_from`, in one wallet transaction; a scheduled end on the old version carries over to the new one. Ending a rule sets its latest version's `effective_to`; no version is ever deleted. (2) **Locks**: every fee write first takes `fee_bounds` `FOR UPDATE`, so fee writes and a change of the bounds run one at a time and each re-reads the versions after the lock; a limit write locks the rule's versions first and then reads them again. The caller sends `baseVersion`; an edit built on an older version answers `wallet.rule_changed` (409), as does a lost `(rule_id, version)` insert. (3) **Time**: `effectiveFrom` null is now; scheduled up to 366 days ahead, never in the past; a new version must start after the latest one (`wallet.rule_change_pending` otherwise), so a scheduled change can't be jumped. (4) **Scope is fixed per rule**: a new version changes only the terms; to change who a rule matches, end it and create another. A new rule whose scope equals a live rule's is refused (`wallet.rule_scope_taken`): the two would only tie. (5) **Validation** in the wallet domain before anything is written (rate within the bounds, `wallet.fee_rate_out_of_bounds` with the bounds; caps more than 0 and minimums not negative, as micro-dollars; bps integers in range; note 3-500 characters), and the bounds trigger's `check_violation` maps to the same code. (6) **Bounds**: refused while any version in force now or scheduled charges a rate outside them (`wallet.fee_bounds_exclude_rules`, naming the rules); ended versions don't count. (7) **Effect**: rules are read fresh from the table on every quote and payment (there is no in-memory or Redis cache to invalidate), so the next quote after `effectiveFrom` uses the new version; a W17 quote already shown keeps its fee until it expires (`fee_quotes`), and a transfer keeps the fee it was prepared with. (8) **Audit**: ops writes the line `PENDING` with the request, then finishes it with the wallet's answer, `before v2 {…} → after v3 {…}` (rates, caps, minimums, gas share and margin, start and end), in the existing `detail` column; the reason is the line's reason and the version's note. | A payment must always trace to the version that priced it, and two admins must never both build on the same version; the database's own lock and constraints are the arbiter, not the portal. Dollar figures stay in micro-dollars on the ops API like every other money figure there. Detail in the existing column rather than new audit columns, so ops needs no migration (another ops change is in flight). | wallet (FeeAdmin, RuleAdminRepository, no migration), ops (`/v1/ops/fees`, `/v1/ops/limits`), the module docs |

## 2026-11-06: Every share is a short link to a server-rendered page

Decided by Pasaka; the design calls below made by the backend session to the premium standard. Every share option in the app stops sending plain text: it makes a link `<SHARE_BASE_URL>/s/{code}` (new module `share`, docs/mobile-integration.md → Share links) that opens a page in any browser, draws a rich preview in chat apps and opens the app when it is installed.

- **The page is built from the server's records, not the phone's.** A receipt comes from the wallet's transfer, a statement from the chama's ledger, an address from the wallet's own row, a person from users. So a Circaso page can't be forged, and whatever isn't the sharer's answers `share.source_not_found`, so a link can't probe for a payment or a group.
- **Privacy.** The stored snapshot holds only what the sharer chose: names (and a statement's notes) only with `showNames` (on by default, a switch in the app), nothing from any chat; chats and moments are end-to-end encrypted and are never shareable. Revoking deletes the snapshot at once; the row stays 30 days only so the page can say "turned off", then the purge job deletes it. A deleted account's links all go.
- **Codes**: 12 base62 characters from `SecureRandom` (about 71 bits), never logged (`ShareCode.toString()` is masked). Views are limited per caller address before the code is read (60 a minute, Redis, the address hashed), creation per user (30 an hour, gateway).
- **Expiry is optional** (1 to 365 days, or until turned off); an invite's link ends with its 7-day invite.
- **Hosting**: plain-Kotlin HTML from the backend behind the existing nginx (no new frontend stack, no template library); the Circaso tokens in light and dark, the logo from assets.circaso.com; `noindex` (meta and `X-Robots-Tag`), `Cache-Control: no-store` (a revoked link must not linger in a cache), a CSP that allows inline style and the logo only, and no script. Open Graph and Twitter `summary` tags use the Circaso icon as the preview image; a generated per-link image would need an image library, not added without asking.
- **Opening the app**: Android App Links (`assetlinks.json`, `SHARE_ANDROID_CERT_SHA256`) and iOS Universal Links (`apple-app-site-association`, `/s/*`) on the share host; the page's "Open in Circaso" is `circaso://s/{code}`; the app calls SH4 and shows the link natively.
- **Public routes outside `/v1`** go through a new `shared-web` seam, `PageContributor`, mounted by the gateway at the root; the gateway's version check, tokens, scopes and idempotency don't apply to them, so the page brings its own guards.
